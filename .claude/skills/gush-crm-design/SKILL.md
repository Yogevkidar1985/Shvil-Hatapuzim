# מערכת העיצוב — פרויקט גוש 6446 · הוד השרון

CRM לניהול בעלי זכויות בעברית מלאה (RTL). קהל היעד: מנהלי פרויקט נדל"ן שעובדים
שעות מול הטבלה ושולחים הודעות WhatsApp. לכן: צפיפות מידע גבוהה אך קריאה,
פעולות תכופות במרחק לחיצה אחת, ומספרים תמיד `tabular-nums`.

## זהות המותג

- **ירוק מקרקעין** (`--brand-*`, ירוק כהה #0f4d3a→#1f785b) — צבע ראשי. כותרת עליונה: גרדיאנט `from-brand-800 to-brand-700`.
- **זהב** (`--gold-*`, #b8924f) — משני, לדגשים (כרטיס סה"כ, שורה נבחרת).
- **ירוק WhatsApp** (#22c55e) — אך ורק לפעולות שליחת הודעות. לא לשימוש דקורטיבי.
- אדום = התנגדות/שגיאה/חסר בלבד. אסור להמציא צבעים — הכול מ-`globals.css` ו-`tailwind.config.ts`.
- פונט: Heebo. אימוג'י משמשים כאייקונים בכל המערכת (💬 ✅ ⏳ 🚫 👥 📞 🗂️) — לא ספריית אייקונים.

## כללי RTL (מחייבים)

- `dir="rtl"` גלובלי; AG Grid עם `enableRtl` — אין לשנות.
- פסי התקדמות: הקונטיינר `dir="ltr"` והמילוי עם `margin-left:auto` כך שהמילוי גדל מימין לשמאל.
- טלפונים ומספרים: `tabular-nums`; מספרי טלפון בפורמט 050-123-4567 (עזרי `format.ts`).
- אין להשתמש ב-`left/right` ישירים ב-Tailwind כשיש חלופה לוגית; לבדוק ויזואלית כל שינוי.

## היררכיית המסך הראשי (מלמעלה למטה)

1. **באנר מותג** — ירוק כהה: לוגו, שם פרויקט, צ'יפי תכנית/גוש, מצב WhatsApp, שמירה, הגדרות.
2. **כרטיסי KPI** (`StatCard`) — לחיצים ומסננים. כל המספרים מחושבים על ה"נוכחי 2026" (92) בלבד; ארכיון 2015 בכרטיס נפרד.
3. **לוח התקדמות** (`ProgressBoard`) — חתימות + איסוף טלפונים; לחיצה מסננת למי שנשאר לטפל.
4. **סרגל פעולות** — חיפוש, צ'יפי סינון (מקור | סטטוס | טלפון), כפתורי פעולה בקבוצות לוגיות, ובקצה: קבוצה + שליחה לנבחרים (הפעולה הראשית — ירוק WhatsApp).
5. **בקרת תצוגה** — פונט A-/A+, גודל טבלה, רווח עמודות (נשמרים ב-localStorage בלבד — העדפה אישית).
6. **הטבלה** — האזור העיקרי; לתת לה כמה שיותר גובה.

## דפוסי רכיבים

- **רדיוסים**: כרטיסים/מודאלים 14-16px (`rounded-2xl`), צ'יפים/תגיות `rounded-full`, שדות קלט `rounded-xl`.
- **צללים**: משתמשים רק ב-`--shadow-xs/sm/md/lg` או `shadow-soft`. אין צל קשה.
- **סטטוסים**: `status-pill` + נקודת צבע; חתם=ירוק, ממתין=אפור, התנגד=אדום.
- **תגיות מידע קטנות** (תבנית הודעה, כפילות, "בעבר"): `rounded-full px-2 py-0.5 text-xs font-semibold` על רקע פסטל.
- **מודאלים**: `Modal` בלבד (כותרת+אייקון+סאבטייטל, `animate-pop-in`). אישור מסוכן — כפתור אדום + ניסוח מפורש.
- **טוסטים**: `useToast` — משוב לכל פעולה אסינכרונית.
- **מצבי ריק**: `EmptyState` עם אייקון, כותרת, ופעולה מוצעת. טבלה מסוננת ללא תוצאות ≠ טבלה ריקה — טקסט שונה.

## AG Grid

- ערכת `ag-theme-quartz` מותאמת ב-`globals.css` — כל שינוי עיצוב טבלה שם, לא ב-inline.
- זום/פונט דרך משתני CSS (`--ag-font-size` = `14 * zoom * fontScale`); שינוי גובה שורה מחייב remount (`key={zoom}`).
- עמודות מערכת (`_messages`, `_group`, `_phoneAddedAt`, `_actions`) עם `suppressMovable`; עמודות נתונים חייבות להישאר גרירות.
- `onColumnMoved` מגיב רק כש-`e.finished` — אחרת הגרירה מתבטלת.

## נגישות ומיקרו-אינטראקציות

- כל כפתור-אייקון חייב `title` + `aria-label`.
- פוקוס: `focus-ring` (טבעת ירוקה רכה) על כל אלמנט אינטראקטיבי.
- `prefers-reduced-motion` מכבה אנימציות.
- מעברים 120-280ms עם easing רך; אין אנימציות ארוכות בזרימות עבודה תכופות.
- קיצור "/" ממקד את החיפוש; Escape מנקה.

## מובייל

- **כלל ברזל: אין גלילה מקוננת במובייל.** הרשימה היא `MobileList` (כרטיסים בזרימת
  הדף, גלילת דף אחת); AG Grid מוצג בדסקטופ בלבד (`hidden md:block`). אסור להחזיר
  טבלה עם גלילה פנימית למסך מגע — זה מרגיש "תקוע".
- הדף במובייל: `min-h-[100dvh]` (dvh! לא vh — סרגל הכתובת של iOS), כותרת לא-דבוקה
  שנגללת ומפנה מקום; בדסקטופ `md:h-screen` + כותרת דבוקה.
- בחירה מרובה במובייל: צ'קבוקס בכרטיס + סרגל פעולה צף תחתון (שליחה/קבוצה/נקה).
- כרטיסי KPI: גלילה אופקית (`no-scrollbar`) במסך צר, wrap במסך רחב.
- לוח ההתקדמות נערם לעמודה אחת; סרגל הפעולות נשבר לשורות.
- אין להסתיר פעולות במובייל — המשתמש עובד גם מהטלפון.
- `overflow-x-clip` על שורש האפליקציה — שום אלמנט לא מותח את הדף לרוחב.

## תהליך אימות חובה לכל שינוי UI

```bash
# 1. סכמה מקומית (להחזיר postgresql לפני commit!)
sed -i 's/provider = "postgresql"/provider = "sqlite"/' prisma/schema.prisma
npx prisma generate && rm -f prisma/dev.db
DATABASE_URL="file:./dev.db" npx prisma db push --skip-generate
# 2. בנייה + שרת
DATABASE_URL="file:./dev.db" npx next build
DATABASE_URL="file:./dev.db" APP_PASSWORD=testpass SESSION_SECRET=testsecret npx next start -p 3990 &
# 3. צילומי מסך Playwright (chromium ב-/opt/pw-browsers/chromium):
#    התחברות → reload (CSS חם) → צילום דסקטופ 1500x900 + מובייל 390x844
# 4. להשוות לפני/אחרי, לוודא RTL תקין, ואז: להחזיר postgresql, למחוק dev.db, commit
```

## אסור

- לשבור את זרימת העבודה הקיימת (סינון בלחיצה, עריכה בתא, גרירת עמודות).
- להוסיף ספריות UI חדשות — הכול Tailwind + הרכיבים הקיימים ב-`app/components/ui`.
- צבעים/צללים מחוץ לטוקנים; טקסט אנגלית בממשק (עברית בלבד).
- לגעת ב-localStorage לנתונים עסקיים — רק העדפות תצוגה. כל נתון עסקי ב-DB בענן.
